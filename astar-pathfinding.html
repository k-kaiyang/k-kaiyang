A* pathfinding without frame spikes

Umapyoi EngineC++20A* GridPathfinder.cpp · PathFindingSystem.cpp

Enemies of different sizes had to chase the player around obstacles without making the game stutter.

Problem

Each enemy needs a path to the player that goes around walls, and bigger enemies can't squeeze through gaps that small ones can.

Constraint

A path search costs time every frame. If many enemies search at once, or one keeps searching for a target it can't reach, frame time suffers.

What I tested

Add: how many enemies were on screen, and what frame time you saw before and after.

What failed

At first every enemy re-planned on the same frame. My first fix also broke: resetting each timer to 0 after a re-plan wiped out the offset that kept enemies apart, so they lined up again.

Add: what this looked like in the game, for example a visible stutter every half second.

What I changed

  • 8-direction A* on a grid, using a priority queue and straight-line (Euclidean) distance as the estimate.
  • Precomputed clearance for each cell, so the search only uses cells wide enough for that enemy.
  • Capped each search at 2,000 steps, so an unreachable target can't stall a frame.
  • Smoothed paths by skipping waypoints that are in direct line of sight.
  • Gave each enemy a re-path timer (0.5 s by default) that starts at a random offset. The timer subtracts the interval instead of resetting to 0, so the offset survives.

What happened

The pathfinder drives 17 Lua AI scripts for the 3 demon types and the 3-phase boss.
